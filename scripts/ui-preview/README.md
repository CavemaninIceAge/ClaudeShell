# Offline workspace previews

Run `scripts/ui-preview/render.sh` after UI edits are stable. The default output is `.impeccable/review/workspace/`.

The harness renders the **actual production `WorkspaceView`**, including the outer navigation rail, title bar, sidebar, inspector, destination pages, composer, and transcript resources. It does not rebuild the interface in an independent mock. Seventeen PNGs cover empty and populated conversation states at 1566×895 (the supplied reference's logical size) in both appearances; narrow conversations at 880×560 in both appearances; History, Library, Images, Apps, and Settings at 1200×800 light; Settings at 1200×800 dark; and rich Markdown at 880×560 dark with a three-line Swift code block and a two-row table. Three additional 1566×895 captures cover the file editor and Git diff in light appearance and command output in dark appearance.

All identity/history/transcript inputs are synthetic in-memory snapshots. The production asset catalog uses its snapshot initializer. PNG thumbnails (each labelled SAMPLE / 合成示例), a Markdown document, and a CSV are created only inside `synthetic-fixtures/` beneath the output directory. The production thumbnail loader reads only these fixture images; no user files are read. Workspace tool captures create an isolated synthetic Git repository below the output directory and execute only fixed fixture commands. That repository is excluded from delivery artifacts. Completed subagents are derived from synthetic native `Agent` tool records. `WorkspaceView` has no bootstrap task. The fixture constructors do not read credentials or real session files, persist preferences, register timers, or start engines. Cocoa preferences use a disposable directory through `CFFIXED_USER_HOME`; `HOME` is unchanged. No app/window is ordered, activated, focused, or made key. No global input is sent.

Native views render using `NSView.cacheDisplay`. WebKit remote-layer caching varies by OS version: the native bitmap may already contain part or all of its paint. Before compositing the **same production WKWebView** snapshot at its real view coordinates, the harness replaces that rectangle with opaque, appearance-resolved `Theme.background`. This prevents doubled text and translucent bubble opacity. This is screenshot composition, not a replacement transcript implementation. The reference-conversation variant uses a real titled AppKit window and the production WorkspaceWindowStyle, including native window controls. Other variants capture the workspace without system window chrome. Every output is rendered at 2× pixel density; metadata keeps logical and pixel dimensions separate. The reference variant reconstructs user-supplied screenshot text and accepts its attachment from the explicit CLAUDEX_REFERENCE_ATTACHMENT environment variable and optional CLAUDEX_REFERENCE_TITLES JSON array; it is visual test data, never evidence of a live model run.

`workspace-preview.json` records dimensions, appearance, web overflow metrics, and checks that each window remained invisible/non-key/non-main. Verify these fields and inspect the PNGs before accepting the UI. These static images do not establish native engine or account behavior; use `scripts/test.sh` for those fixtures.

Native chrome geometry is checked in an additional unordered titled host. The checks include the real controls, their parent bounds, and window/content frame sizes. Inactive window-control color is expected; the harness never activates a window to obtain active colors.
