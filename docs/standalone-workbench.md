# 在 Claudex Shell 中完成日常工作

Claudex Shell 0.4.0 的目标是让 Claude Code 与 Codex 的日常工作都在同一个窗口完成。运行时需要本机原生 CLI；不需要启动 Claude、Codex 桌面窗口或另开终端。

## 首次连接

在「应用」页检测引擎，或指定 `claude` / `codex` 的可执行文件。应用会查找常见 CLI 安装位置，以及已安装 Codex / ChatGPT 应用内的 CLI。自定义路径无效时会显示错误，不会悄悄换用另一个程序。若本机尚未安装 CLI，先按相应引擎的官方方式安装，然后重新检测。

可在应用内添加 Claude 账号、Codex / ChatGPT 账号、Codex API Key 或 GLM / API 提供方，也可保存本机已有登录态。Codex 的设备登录会显示授权地址与设备码，由你点击打开认证网页；API Key 经 stdin 交给原生 CLI，不出现在命令参数或日志里。登录使用独立配置目录，成功后将凭据保存在钥匙串。账号选择只作用于本应用；向终端或 Codex App 推送仍是独立操作。

## 项目与对话

- 「新聊天」或 `⌘N` 在当前项目中开始；`⇧⌘N` 选择工作目录并保存项目。
- 有内容的草稿不会被新聊天复用。未发送文字、附件（包括粘贴的图片）、模型选择、上次打开的会话及保存项目会跨重启保留。
- 侧栏切换为 Projects 可找到保存的空项目；`⌘K` 可搜索对话和保存的项目。
- 在历史页切换「已隐藏」可恢复隐藏的会话，原生会话文件始终保留。
- 已开始的会话使用原引擎继续；Codex 会话可通过「用 Claude 接管」创建包含可见历史上下文的 Claude 会话，原记录保留。

## 文件、改动与命令

顶栏的文件夹和命令按钮打开应用内工作区。宽窗口并排显示，窄窗口使用面板。

| 操作 | 快捷键 | 行为 |
| --- | --- | --- |
| 项目文件 | `⌥⌘E` | 按需展开目录、查看和编辑文本、明确保存、把文件添加到当前对话 |
| 代码改动 | `⌥⌘G` | 读取 Git 状态及差异，包含未跟踪文件 |
| 命令与输出 | `⌥⌘J` | 输入命令后运行，查看输出、退出码并停止执行 |

文本编辑器支持最多 2 MiB 的 UTF-8 普通文件。保存前核对磁盘内容及文件身份，遇到外部修改不会覆盖；符号链接不在文件树中展开。目录切换保留各自的编辑草稿，同时取消旧目录中的读取和运行命令。收起面板会保留当前编辑内容和命令状态。编辑器未保存的内容在本次应用运行期间保留；需要跨重启保留时请明确保存文件。

命令面板为有界管道输出，关闭 stdin，不提供交互式 PTY。需要工具补充输入的操作可在对话中交给原生引擎，或调整为非交互命令。Git 查看关闭外部 diff 和 textconv，查看改动本身不提交、不修改项目。

资料库、图片和聊天中的本地文件链接在应用内预览，支持常见图片、PDF、文本和文档；可直接附加到当前对话。

## 原生引擎与范围

Claude 使用原生 stream-JSON 会话，Codex 使用 app-server。工具执行、推理和原生历史由各自 CLI 管理；应用负责呈现消息、收集审批和表单答案、保存界面元数据。审批只提供引擎允许的选项。停止失败会清理旧进程，避免迟到事件影响下一次对话。

原生内置工具及项目配置可以在对话中使用。账号隔离不会自动复制全局 MCP、插件或云端应用授权。官方专有的云应用市场、云任务和独立图片生成服务没有被重新实现。

应用元数据仍位于 `~/Library/Application Support/Claude Shell/`，保持旧版本兼容。草稿及附件保存在权限为 `0600` 的 `workspace-session.json`；该文件不包含认证凭据。更新保留用户数据和设置。

协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Codex 身份验证](https://learn.chatgpt.com/docs/auth)、[Claude Code 程序化运行](https://code.claude.com/docs/en/headless)。实现同时对照本机 CLI 导出的协议 schema；版本差异以本机支持的字段为准。
